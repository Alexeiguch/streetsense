# Perception review — 4 November 2026

The default pipeline keeps the existing detector weights and confidence thresholds. This review fixes temporal-state errors, improves segmentation caching, and checks the live Meta integrations. The crossing rule remains local **walk AND validated Muse yes**. The review preceded the separately authorized [offline 3D experiment](RECONSTRUCTION_EXPERIMENT.md).

## Fixes

| Issue | Result |
|---|---|
| Background Muse hazard text bypassed the crossing-answer renderer and was repeatedly requeued from an old image | Validate the reply, filter crossing permission and signal claims with the existing guidance sanitizer, ingest each report once, and expire pending advice from capture time. Background report age defaults to 3 seconds. The text filter is a guard, not a semantic safety proof. |
| Speech rejected an old crossing answer while the returned `fuse.decision` could still say `go` | Both now reject stale evidence. Future capture timestamps also produce the fixed wait response. |
| Rewinds and resolution changes retained pixel-coordinate tracks, walk votes and cached segmentation | Reset detector tracking, approach history, light votes, crosswalk hysteresis, depth calibration, frame history, pending alerts and model evidence. Results from earlier asynchronous requests are invalidated. |
| Segmentation was refreshed only by frame count | Also refresh after 0.5 seconds and after geometry/time resets. Cache the road-or-sidewalk boolean mask with the segmentation result instead of recomputing it for each crosswalk pass. |
| Approach history survived lost tracks and class changes; a 64-frame buffer lost the time window at high FPS | Expire missing/future histories, clear history on class change, and sample history in time while evaluating the current box every frame. |
| A stronger tiled light box could discard the local track ID during NMS | Retain the stronger box and borrow the closest overlapping local track's ID without mutating input detections. |
| Background SAM sometimes shared the caller's mutable frame buffer | Copy the request frame, reject future/stale results, invalidate requests on scene reset, and recover if worker startup fails. |
| SAM previews drew request-resolution coordinates on the original-resolution image | Scale boxes and masks, clip masks at image edges, and draw box edges after blending. Verified visually on live responses. |
| The global signal CNN could compile concurrently or reuse an OpenVINO infer request concurrently across web sessions | Lock initialization and inference; copy output while holding the inference lock. |

Validation: **426 passed, 1 skipped** (`python -m pytest -q`). Regression coverage includes rewind, resolution changes, slow cameras, 200 FPS approach history, class/ID reuse, asynchronous result invalidation, frame ownership, stale queued advice, unsafe background phrases, SAM preview scaling/clipping, and concurrent CNN inference. Network tests use stubs; the paid smoke check is separate.

## Same-host performance

Python 3.14.0, macOS 26.6.2 arm64; CPU OpenVINO. YOLO11s at 640 inference size, SegFormer-B0 every six frames, 1280-pixel source width, annotation off, SAM fallback and background API calls off. Three windows: DC red at 1s, DC walk at 10s, Tyumen at 8s. Each run decodes 65 frames, excludes five warmup frames, and measures 60; two repeats per window, **360 measured frames per version**. Baseline is repository commit `464b298`.

Dependencies: ultralytics 8.4.202, torch 2.14.1, OpenVINO 2026.4.1, numpy 2.4.3, transformers 5.18.0. YOLO weights SHA256: `85a76fe86dd8afe384648546b56a7a78580c7cb7b404fc595f97969322d502d5`.

| Metric | Before | Final defaults |
|---|---:|---:|
| Pooled throughput (frames / total measured seconds) | 16.11 FPS | 15.78 FPS |
| Median of six run throughputs | 16.29 FPS | 16.78 FPS |
| Mean amortized crosswalk-stage time | 0.630 ms | 0.356 ms |
| Detection counts, light states, spoken alerts, continuity proxy | Reference | Identical on all six runs |

Crosswalk-stage time fell about **43%** with the cached mask. End-to-end results are noisy: pooled throughput fell 2.1%, while median run throughput rose 3.0%. The first final-default run had 178ms p95, versus 85–101ms for the other five; the baseline first run was also slower. Five warmup frames and short sequential runs do not establish a general speedup or a statistically resolved regression. These Mac results are not directly comparable to the Linux figures in BENCHMARK.md. Startup/export, capture, annotation and speech costs are excluded.

### Tracking experiment kept optional

`DetectorConfig(track_conf=.10)` lets ByteTrack associate low-confidence boxes, while emitted detections still require the original class thresholds. This follows the low-score association mechanism described in the [ByteTrack paper](https://arxiv.org/abs/2110.06864).

On each Tyumen repeat, the adjacent-frame IoU continuity proxy changed from **4/1059** ID changes to **3/1052**, but person detections changed **558 → 551** and cars **381 → 382**. DC output counts and light states were unchanged. This is neither ground-truth IDF1 nor detection recall. Because the detection coverage changed, the lower floor remains **opt-in** (`track_conf=None` by default). A labelled video recall/ID-switch evaluation should precede a default change.

Reproduce, with sample downloads and model dependencies installed:

```bash
python scripts/benchmark_review.py --label after --frames 60 --repeats 2
python scripts/benchmark_review.py --label low-score --track-conf .10 --frames 60 --repeats 2
```

Full measurements: [before](review_2026_11_04/before-performance.json), [final defaults](review_2026_11_04/after-performance.json), [optional low-score tracking](review_2026_11_04/low-score-performance.json). Source credits are in [samples/README.md](../samples/README.md). On this host the filesystem sandbox blocks OpenVINO's CPU feature probe, so the native inference checks ran with normal hardware access.

Local reader warmed on five nearby frames; SAM fallback and background reasoning disabled to avoid extra calls. Samples match existing labels in `eval/muse_labels.csv`, but decoding uses OpenCV timestamp seeks, so these are approximate sample times, not a new frame-exact accuracy benchmark.

| Sample | Local | Muse, both repeats | Fusion, both repeats |
|---|---|---|---|
| DC 3.0s, red | red | no / red | stop |
| DC 13.8s, walk | walk | yes / green | go |

All eight replies passed schema validation. No go on the four labelled red/countdown requests; the two unclear requests also did not produce go. Four samples and repeated requests are too small to claim model accuracy or live navigation safety. The Tyumen result illustrates why Muse alone must not authorize crossing.

Muse wall time: **mean 4.06s, median 3.92s, p95 6.09s**, range 2.12–6.50s. These are on-demand 1024-pixel requests; the background image is smaller. Slow background replies exceeding the 3s capture-age window are deliberately dropped.

Two **SAM 3.1** calls at longest side 768:

- DC walk, `traffic light`: two boxes and two decoded masks; API 2.506s, wall 2.565s.
- Tyumen, `crosswalk`: one box and one decoded mask; API 1.165s, wall 1.334s.

Signal boxes aligned with the pedestrian and vehicle heads; the crosswalk mask covered visible foreground stripes. Visual inspection confirms coordinate alignment, not segmentation IoU. The DC signal call exceeded the fallback's default 1.5s capture-age limit: an empty fallback result can be correct under that policy. SAM remains advisory/off the default fast path; no freshness threshold was relaxed.

## 3D reconstruction: research recommendation

**Useful future research for local geometry; defer a full reconstruction pipeline for this submission.** This was an engineering assessment from the sources below, before a local 3D benchmark. A later, separately authorized [offline experiment](RECONSTRUCTION_EXPERIMENT.md) now implements and measures MapAnything without integrating it into the production pipeline.

| Meta project | What it provides | Fit for StreetSense |
|---|---|---|
| [MapAnything](https://github.com/facebookresearch/map-anything) | Metric geometry from images and optional calibration, poses or depth; depth, camera and point-cloud outputs. Apache code; select the Apache checkpoint for commercial-friendly model licensing, since the default checkpoint is CC-BY-NC. | Best first offline candidate for evaluating curb geometry, camera motion and relative obstacle placement. It still needs validation on a moving street camera. |
| [VGGT](https://github.com/facebookresearch/vggt) | Joint camera, depth, point and track predictions. Its README reports a May 2026 memory fix and VGGT-Omega release. Code and checkpoint licenses differ; the commercial checkpoint requires access approval. | A useful geometry baseline. Recheck current implementation and checkpoint rather than relying on older memory/runtime figures. |
| [SAM 3D Objects](https://github.com/facebookresearch/sam-3d-objects) | Full object shape, texture and layout from a single masked image, including occluded objects. The [official setup](https://github.com/facebookresearch/sam-3d-objects/blob/main/doc/setup.md) calls for Linux and an NVIDIA GPU with at least 32GB VRAM. | Better suited to scene visualization/assets than measured free-space evidence on this CPU Mac. Inferred hidden surfaces should not be treated as observed pavement. |

Potential benefit: short-lived geometry may stabilize distance estimates, compensate for camera motion, and distinguish curb/step height from flat markings. The risks to test are dynamic cars/people, weak texture, motion blur, rolling shutter, occlusion, scale error and stale geometry. A good-looking mesh is not evidence of a traversable route.

The next experiment should first establish calibrated depth/distance errors on measured scenes using the existing depth module. Then compare MapAnything and current VGGT on a small offline street set, mask moving objects, and measure metric error, curb-height error, free-space false negatives, pose drift, p95 latency and peak memory. Only consider an asynchronous, expiring local geometry layer if it improves those measurements. Reconstruction must never authorize crossing or refresh stale walk evidence.
